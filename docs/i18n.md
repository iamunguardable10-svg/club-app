# App-Sprachen (i18n)

Stand 2026-09-26. Die App ist auf Englisch geschrieben; weitere Sprachen kommen als JSON-Dateien
dazu. Die Doku bleibt deutsch.

## So ist es gebaut

```
src/shared/i18n/
  locales.ts          Liste der Sprachen (Code + Name in der Sprache selbst)
  translate.ts        Nachschlagen: Platzhalter, Mehrzahl, Rückfall auf Englisch (ohne React)
  index.ts            useT(), useLocale(), currentLocale(), setLocale()
  LanguagePicker.tsx  Auswahl auf der Startseite (oben rechts) und in Settings → This device
  messages/en.json    Quelle, alle Texte
  messages/de.json    Übersetzung (gleiche Schlüssel)
scripts/check-i18n.mjs  Prüfung in der CI (npm run check:i18n)
```

- **Sprache pro Gerät**: gespeichert über `repository.ts` (einzige Stelle mit localStorage).
  Ohne Wahl gilt die Browsersprache, wenn es sie gibt, sonst Englisch.
- **Wechsel lädt die Seite neu**, damit auch Datum und Zahlen (`src/shared/format.ts`) folgen.
- **Server-Render ist immer Englisch**; die Sprache greift direkt nach dem Laden. Daten und Datumswerte
  erscheinen ohnehin erst nach dem Laden (die Daten liegen im Browser).
- **Datum/Zeit/Zahlen** nie selbst formatieren, sondern `formatDay`, `formatTime`, `formatWeekday`,
  `formatDecimal` … aus `@/shared/format` nehmen (Englisch bleibt „Fri 25 Sep · 16:30“).

## Regeln für Code

1. Jeder sichtbare Text geht über `const t = useT()` und `t('bereich.teil.was')`.
2. **Schlüssel**: flach, mit Punkten, nach Bereich: `start.signIn.title`, `load.explainer.caveat`,
   `coach.session.delete`. Bereiche: `common`, `language`, `start`, `auth`, `onboarding`,
   `athlete`, `load`, `calendar`, `coach`, `club`, `settings`, `messages`, `errors`.
3. **Platzhalter** `{name}`: `t('start.welcomeBackName', { name })`. Nie Sätze aus Stücken
   zusammensetzen („Welcome back“ + „, “ + Name), weil die Wortstellung je Sprache anders ist.
4. **Mehrzahl** über `count`: Schlüssel `x_one` und `x_other` (Sprachen mit mehr Formen ergänzen
   `_few`, `_many` …; `_zero` optional). Aufruf `t('x', { count })`.
5. **Kein HTML in Texten** außer `<b>…</b>` für fett gesetzte Wörter mitten im Satz, dazu
   `{name}` für ein Symbol an einer Stelle im Satz: `rich(t('…'), (chunk) => <strong>{chunk}</strong>,
   { icon: <ShareIcon /> })` aus `@/shared/i18n/rich`. Die CI prüft, dass Übersetzungen gleich viele
   Tags haben. Links: eigener Schlüssel für den Linktext.
6. **Nicht übersetzt** werden: „Club OS“, RPE, ACWR, AU, Namen, Quellenangaben (Autor, Zeitschrift).
7. Schlüssel aus Variablen nur über eine typisierte Liste (`Record<…, MessageKey>`), nie
   zusammengesetzt (`t(\`x.${role}\`)`) — so findet die Prüfung jeden Schlüssel.
8. Ein neuer Text kommt **zuerst nach `en.json`**. Die anderen Sprachen dürfen hinterherhinken
   (es erscheint Englisch), die CI warnt nur.
9. **Fehler**: Die Datenschicht bleibt ohne Sprache. Kennt sie einen Fehler, gibt sie den
   Schlüssel mit (`new LocalDataError(englisch, cause, 'auth.error.wrongPassword')`); die
   Oberfläche zeigt `errorText(t, caught)`. Fehler aus einem `useEffect` (z. B. beim ersten
   Laden) roh speichern und erst beim Anzeigen mit `errorText` übersetzen: sie können eintreffen,
   bevor die Sprache nach dem Laden greift. Braucht der Text Werte, gehen sie als viertes
   Argument mit (`messageParams`); ein Wert, der selbst ein Schlüssel ist, wird mit übersetzt
   (`data.withDetail`: „{message} ({detail})“). `OfflineError` trägt ebenfalls einen Schlüssel.

## Was die CI prüft (`npm run check:i18n`, `npm run test:i18n`)

- Fehler: keine gültige flache JSON-Datei, leerer Text, Schlüssel in einer Übersetzung, den
  Englisch nicht hat, andere Platzhalter als Englisch, `t('…')` im Code ohne Eintrag in `en.json`.
- Warnung: noch nicht übersetzte Texte (mit Zählung je Sprache), unbenutzte Schlüssel.

## Neue Sprache hinzufügen

1. `messages/<code>.json` anlegen (z. B. `fr.json`) — übersetzt mit dem Prompt unten.
2. In `locales.ts` eintragen: `{ code: 'fr', name: 'Français' }`, in `translate.ts` die Datei in
   `CATALOGS` aufnehmen.
3. `npm run check:i18n` muss grün sein; dann erscheint die Sprache in der Auswahl.

## Übersetzungs-Prompt (für ein günstiges Modell)

Die ganze `en.json` und (falls vorhanden) die bisherige Zieldatei mitgeben:

```
You translate the UI texts of "Club OS", a team app for sports clubs (coaches and players;
sessions, availability, training load). Target language: <LANGUAGE> (<code>).

Input: en.json (source) and optionally the current <code>.json.
Output: ONLY the complete <code>.json, valid JSON, same keys as en.json, nothing else.

Rules:
- Keep every key exactly. Translate only the values.
- Keep placeholders like {name}, {count}, {club} unchanged and use each one the source uses.
- Keep <b>…</b> tags: put them around the words that mean the same as in the source.
- Keys ending in _one/_other are plural forms. Add the forms your language needs
  (_zero, _two, _few, _many) with the same base key; keep {count} where the number is shown.
- Do not translate: Club OS, RPE, ACWR, AU, author names, journal names.
- Short, friendly, direct; the app speaks to the user informally (German: "du").
  Buttons are short verbs. Do not add explanations or punctuation that the source lacks.
- Sports terms as used in clubs in that country (e.g. German: Einheit, Training, Spiel, Kader).
- If a value in the existing <code>.json is already correct, keep it unchanged.
```

Danach: Datei ersetzen, `npm run check:i18n` laufen lassen, Fehler (meist Platzhalter) von Hand
beheben.

Deutsch (`de.json`) enthält die Texte aus Schritt 1 und 2 (Einstieg für den Pilotverein). Ab
Schritt 3 kommen neue Texte nur nach `en.json`; alle Sprachen, Deutsch eingeschlossen, übersetzt
Ben am Ende mit dem Prompt in einem Rutsch.

**Gespeicherte Titel:** Die App speichert manche Titel selbst auf Englisch (Einheit „Team
training“, eigenes Training „Strength“). Angezeigt werden sie über `displayTitle()` in der Sprache
des Betrachters; selbst getippte Titel bleiben, wie sie sind. Beschriftungen aus der Datenschicht
(`LOAD_TYPE_LABELS`, `loadZone().label`, Prognose-Grundlage) zeigt die Oberfläche über eigene
Schlüssel (`loadTypeLabel`, `zoneLabel`). Ebenso die eingebauten Staff-Rollen
(`displayRoleName()`: „Head Coach“ …) und die Vereinsrollen (`clubRoleText()`).

**Vollständigkeit (Stand Bereich 5):** Ein Probe-Build, der jeden übersetzten Text markiert, zeigte
auf allen Demo-Seiten (Spieler, Trainer, Verein; Handy und Desktop; alle Reiter) keinen
unmarkierten Oberflächentext mehr, nur Daten (Namen, Teams, Hallen, Nachrichten) und Datumswerte
aus `format.ts`. Nicht übersetzt bleiben absichtlich: die Seitentitel im Browser-Tab
(`metadata`, Server) und der Operator-Text „Unknown error“ in Fehlerberichten.

**Tipp für die Übersetzung:** `en.json` hat rund 1 400 Texte. Bricht ein günstiges Modell die
Ausgabe ab, die Datei in Stücke (z. B. je 300 Schlüssel) teilen, jedes Stück mit demselben
Prompt übersetzen und die Ergebnisse zusammenfügen; danach `npm run check:i18n`.

**Texte vom Server (6a):** Der Server schreibt seine Meldungen weiter auf Englisch
(`raise exception '…'`, Apple-Kalender-Funktion). `src/shared/data/serverMessages.ts` ordnet jeder
bekannten Meldung einen Schlüssel `server.*` zu; Datenbank-Aufrufe werfen darüber einen
`LocalDataError` mit Schlüssel, und die App zeigt ihn mit `errorText` übersetzt. Unbekannte Texte
erscheinen wie bisher. **Neue Meldung auf dem Server:** Zeile in `SERVER_MESSAGES` und derselbe Text
in `en.json` — `npm run test:i18n` prüft, dass beide gleich sind. Der „Not saved …“-Hinweis kommt als
`rejectedNotice` (Schlüssel + Werte); `rejected` bleibt Englisch für die Fehlerberichte.

Noch Englisch bis 6b: Push-Nachrichten und die Mails von Supabase (Bestätigen, Passwort
zurücksetzen).
